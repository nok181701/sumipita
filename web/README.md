# スムピタ Web

東京23区の町丁目ごとに、治安・洪水・高潮・地盤の4軸を並列表示するダッシュボード。

## 起動

```bash
cd web
npm install
npm run dev
```

## データの再生成

`cache/sumupita_scores.csv` を更新したら、リポジトリのルートで:

```bash
python3 etl/build_web_data.py
```

`web/public/data/` に以下が書き出される。

| ファイル | 内容 | サイズ |
|---|---|---|
| `index.json` | 検索用インデックス（全3,142件・スコアのみ） | 約490 KB |
| `wards/{区名}.json` | 区ごとの詳細（生の犯罪件数・浸水深） | 合計 約2.2 MB |

区ごとに分割しているのは、R2のGeoJSONを24ファイルに分ける方針と揃えるため。
D1 + Workers に移行するときは `Dashboard.tsx` の `fetch` をAPI呼び出しに差し替えるだけで済む。

## 設計上の約束ごと

守らないとユーザーを誤解させるので、変更するときは必ず理由を残すこと。

**1. 4軸を合成して総合点を出さない**
治安と災害3軸の相関は0.06前後で実質ゼロ。災害3軸すべて70点以上の413件のうち、
治安も70点以上なのは152件（37%）だけ。総合点にすると片方を必ず見落とす。

**2. 「データがない」と「リスクがない」を区別する**
世田谷区の高潮スコア100は「対象区域外」であって「調査したが安全」ではない。
一覧のバーでも満点として描かず、空バー＋点線枠で表示している。
`flags.tide_in_scope` / `flags.flood_covered` / `flags.scored` で判定する。

**3. 区の平均値を出さない**
犯罪件数の分母が夜間人口のため、業務地区を多く含む区で実態と大きくずれる。
千代田区の区平均は28.5だが、住宅地の四番町は86.5。

**4. スコアだけでなく生値を必ず併記する**
「治安スコア85」ではなく「昨年の空き巣2件」まで示す。スコアだけでは納得感がない。

**5. 出典表記を落とさない**
全データがCC BYで表示義務がある。`index.json` の `sources` から機械的に出している。
